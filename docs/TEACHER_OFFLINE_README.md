# 植物叶片病害识别系统——课程演示版

本项目面向“基于图像数据的农作物病虫害识别与防治决策”课程任务，使用PyTorch和ResNet18建立叶片图像分类模型，通过Streamlit提供中文上传识别页面。本交付包包含网页代码、最终模型、Python解释器及已验证的依赖，供老师离线运行、查看实验结果和审阅代码。

推荐双击根目录 **`项目说明.html`** 阅读本说明的排版版；浏览器打开即可，不需启动Python，也不需联网。

## 一、如何运行

1. 使用Windows 64位电脑，将**整个ZIP完整解压**到可写的本地文件夹，建议保留至少8 GB可用空间。不要在压缩软件内部直接运行，也不要只复制启动文件。
2. 双击根目录的 **`启动网页.bat`**。无需安装Python、PyCharm、Anaconda或依赖，不需要管理员权限或联网下载模型。
3. 保留启动窗口。启动器检查包内模型后，自动打开本机网页，默认地址为 **http://127.0.0.1:8601**。若端口已占用，会在8602～8610中选择可用端口，实际地址显示在窗口中。若浏览器未自动打开，复制窗口内的地址到浏览器。
4. 在页面上传一张静态叶片图片，确认预览后点击“开始识别”，查看中文及英文类别、Top3分数和防治参考。点击展开区可查看全部支持类别与模型实验结果。
5. 演示结束，在启动窗口按 **Ctrl+C**；若询问是否终止批处理，输入Y。关闭浏览器标签页不会自动停止Python服务。

本版**默认使用CPU**，不要求NVIDIA显卡或CUDA驱动。包内保留现有PyTorch CUDA构建以复用已验证依赖，但通过启动入口禁用GPU选择；CPU执行同一模型和预处理，不改变分类规则或输出概率。首次导入依赖可能需要等待，CPU响应速度与电脑性能有关。

本包针对Windows x64，不适用于macOS、Linux或ARM版Windows。已在制作电脑上以独立目录及包内解释器验证；尚未在老师的另一台实体电脑验证，操作系统组件或安全软件差异仍可能影响启动。本机验证情况见`results/offline_verification.json`。

### 遇到问题

- 首先双击 **`启动前检查.bat`**。正常时输出`status: passed`，并执行一次CPU合成图片推理；这只是运行检查，不是模型效果评价。
- 模型校验失败或文件缺失：重新完整解压本交付包，不要随意替换权重。启动日志位于`.runtime/startup.log`。
- 无法访问页面：确认启动窗口仍运行，并使用该窗口实际显示的地址；端口可能不是8601。
- 安全软件拦截、缺少系统DLL等错误：保留完整错误信息交由项目作者定位，不建议关闭安全软件或从不明来源下载DLL。
- 本包必须放在有写权限的位置，运行日志及临时缓存放在包内`.runtime/`；上传图片默认只在内存处理，不自动保存。

也可以在本目录的PowerShell中执行：

```powershell
& '.\runtime\python.exe' -I '.\portable_start.py'
```

只检查而不打开网页：

```powershell
& '.\runtime\python.exe' -I '.\portable_start.py' --check
```

## 二、系统实现了什么

| 课程任务 | 当前实现情况 |
| --- | --- |
| 图像数据治理 | 已完成可读性检查、SHA256字节去重、固定划分、训练在线增强和类别数量分析；另有类别均衡对照实验 |
| 作物—病害多分类模型 | 使用ImageNet预训练ResNet18，输出39类分类结果 |
| 严重程度／风险等级 | 提供按预测类别匹配的参考风险规则；没有实现从病斑面积测量真实轻、中、重等级 |
| 图片上传可视化 | 提供中文网页、图片预览、Top1与Top3、可复制中英文类别表 |
| 报告与防治参考 | 包含课程报告、错误分析、来源链接及按类别整理的防治管理参考；不是自动施药处方 |

39类由**26类病害／虫害、12类健康、1类无叶片背景**组成，并非39种病害。背景类只是训练标签之一，不能据此认为模型能可靠拒绝所有非叶片图片。

页面支持JPG、JPEG、JPE、JFIF、PNG、WebP、BMP、TIF、TIFF、GIF、AVIF静态图片。单张最大10 MB、2000万像素，验证真实文件格式，拒绝损坏、伪装后缀和多帧／多页文件，保留Pillow安全限制。

模型输出必须归入现有类别，不包含所有作物或所有病害。网络图片、复杂背景、光照变化、多片叶子等与训练数据不同的情况可能识别错误。预测概率是分类模型的输出分数，不等同于诊断可靠性，也没有额外设置未经验证的低分拒识阈值。

## 三、模型如何完成识别

```text
浏览器上传图片
  → Python检查文件、解码并按EXIF方向转为RGB
  → 短边缩放到256，中心裁剪224×224
  → 转为张量、按ImageNet均值与标准差归一化
  → ResNet18提取特征，39类分类头输出39个分数
  → Softmax得到分类分数，显示Top1及Top3
  → 按预测类别查找对应的风险规则与资料来源
```

推理使用`eval()`和`inference_mode()`，不计算训练梯度，不更新模型参数。确定性预处理与原验证及最终测试保持一致：双线性插值、antialias开启、均值`[0.485, 0.456, 0.406]`、标准差`[0.229, 0.224, 0.225]`。推理不加入随机裁剪或翻转。

ResNet18的主干负责提取叶脉、斑点、颜色和纹理等特征；分类头是最后的线性层，将512维特征映射到39个类别。中文名称仅帮助阅读，模型编号与英文类别名严格使用检查点中的映射。

网页与命令行共用`inference.py`，模型构造与预处理复用`smoke_utils.py`，避免出现页面与实验使用不同模型逻辑。启动时核对模型SHA256，网页通过缓存复用已加载模型，连续识别不需要重新训练或下载权重。

## 四、数据与实验划分

使用现有`Plant_leave_diseases_dataset_with_augmentation`，共39类、原始61,486张图片，可读性检查损坏0张。按既有SHA256结果每个字节哈希保留一个代表参与实验，得到61,274张；原始图片保持原位。

| 集合 | 数量 | 用途 |
| --- | ---: | --- |
| 训练集 | 42,890 | 更新分类头参数 |
| 验证集 | 9,192 | 选出验证loss最低的模型并控制早停 |
| 测试集 | 9,192 | 模型方案确定后的最终评价，已经完成 |

划分随机种子42，按类别尽量达到70%／15%／15%；smoke阶段已使用图片及其相同SHA256代表仅进入训练集。三个集合间已知路径与SHA256交集为0，全部39类均有样本。正式划分元数据和锁在`experiment_source/splits/formal_sha256_seed42_v1/`。

**本划分已排除已知SHA256字节重复，但未排除增强同源关系，测试成绩可能偏乐观，不能直接代表独立叶片或真实拍摄场景的泛化能力。** 文件哈希不能发现旋转、翻转等字节不同但来源相同的图片。

演示推理不依赖原始数据集。本包不附原始数据，也不自动重新运行测试集；历史报告中的案例已经查看，仅用于报告说明。

## 五、训练方法与真实训练情况

网页锁定第一版完整实验的**第3轮最佳模型**。该实验从已缓存的ImageNet预训练参数开始，重新初始化39类分类头，没有接着训练smoke模型。

| 配置 | 实际设置 |
| --- | --- |
| 模型 | ResNet18，ImageNet1K V1预训练 |
| 训练范围 | 冻结主干，只训练39类分类头 |
| BatchNorm | 主干保持eval，运行均值和方差不更新 |
| 损失与优化器 | CrossEntropyLoss、Adam |
| 学习率 | 0.001 |
| batch_size／num_workers | 32／0 |
| 随机种子 | 42 |
| 训练增强 | 224随机裁剪，scale 0.8～1.0、ratio 0.9～1.1；水平翻转概率0.5 |
| 验证预处理 | 与推理一致的确定性预处理，无随机增强 |
| 停止与选模 | 最多10轮，验证loss最低保存最佳，耐心值3 |
| 实际训练设备 | NVIDIA GeForce RTX 4060 Laptop GPU |

交叉熵衡量模型分数与真实标签之间的差异。反向传播计算分类头参数的梯度，Adam据此更新参数；网页预测只做前向计算，没有这些更新步骤。原实验已核对分类头确实更新、主干参数及BatchNorm统计不变，并通过独立进程保存重载检查。

| 轮次 | 训练loss | 训练accuracy | 验证loss | 验证accuracy | 训练＋验证耗时（秒） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 0.5455 | 87.86% | 0.3159 | 90.69% | 274.60 |
| 2 | 0.1890 | 94.96% | 0.2493 | 92.40% | 256.43 |
| **3（最佳）** | **0.1451** | **95.75%** | **0.2089** | **93.30%** | **204.35** |
| 4 | 0.1252 | 96.17% | 0.2123 | 93.16% | 193.47 |

| 6 | 0.1003 | 96.76% | 0.2178 | 93.17% | 241.10 |

实际6轮后早停。训练与验证累计约1,366.87秒（22分46.87秒，不含首轮人工检查等待）；主程序总耗时约1,422.00秒（23分42秒）。第3轮之后训练loss继续下降、验证loss没有改善，出现过拟合倾向，因此保留第3轮，而不是使用最后一轮。

## 七、风险、防治参考与能力边界

现有数据只有类别标签，没有病斑掩膜、轻中重标签、田间发病率或经过专家确认的严重程度标准，因此当前分类模型不能从图片可靠输出真实严重等级。页面的参考风险来自预先整理的类别规则，不能解释为模型测量出的病情轻重。

防治资料按预测类别匹配已有参考内容和大学推广／农业机构链接，不是联网实时检索或由模型生成的药方。应先核对作物与症状，再结合田间调查、当地规范和植保人员意见。资料链接需联网打开，但断网不影响模型推理及包内报告阅读。

真正的严重程度模型还需要病斑标注或明确分级标签、作物及病害对应的分级标准，并在独立场景验证。当前未实现真实轻中重评估，也未验证自动施药决策。
